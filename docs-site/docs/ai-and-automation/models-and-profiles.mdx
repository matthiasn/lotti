# Route work with models and profiles

A provider tells Lotti where to connect. A model records one provider model ID
and its capabilities. An inference profile then assigns those models to the
jobs Lotti understands. This keeps “which model handles audio?” out of every
individual task and automation rule.

## Review saved models

Open **Settings → AI Settings → Models**. The models form one list. Above
it, one filter chip per provider and the **Text**, **Vision**, **Audio** and
**Reasoning** chips narrow it, and the search field finds providers, models
and profiles by name.

Three controls sit at the top of AI Settings:

- **Concurrent agent wakes** limits how many different agents may run
  inference at once.
- **Update cadence** sets how often task agents update on their own when
  neither the task nor its category sets it. **At most hourly** still updates
  right away after a recording, a stopped timer or a task marked done.
- **Default inference profile** is the fallback for agents without a
  configured inference route on this device.

A higher **Concurrent agent wakes** value can improve throughput, but it also increases simultaneous provider requests and local
device load. Keep it conservative when a provider has strict rate limits or a
local model server has limited memory.

## Add or edit a model

Select a model card, or use **+** to add one. A model definition includes:

- the provider connection;
- a friendly display name and optional description;
- the provider's exact model ID;
- the maximum completion-token limit;
- input and output modalities; and
- capability flags such as reasoning or function calling.

Use the exact identifier expected by the provider. The display name is only for
people; changing it does not change what the provider runs. Do not claim image,
audio, tool, or reasoning support unless that model and endpoint actually
provide it.

## Build an inference profile

Open **Settings → AI Settings → Inference Profiles**. Each profile is a reusable
routing policy. The overview shows which model serves each configured slot.

<ManualScreenshot
  caseId="ai/profiles"
  alt="Lotti inference profiles for Project Waddle Command, Habitat Local-First, and Fish Diplomacy with their routed models"
  caption="Profiles can optimize for different boundaries: a broad cloud profile, a desktop-only local profile, or a specialist reasoning profile."
/>

Edit a profile to assign models for the capabilities you use:

- **Thinking** is the required general text model.
- **Chat model** answers in chats; it uses the thinking model when unset.
- **Thinking (High-End)** can handle work that explicitly requests the more
  capable reasoning path.
- **Image Recognition** analyzes images.
- **Transcription** converts audio to text.
- **Audio post-processing** corrects a transcript against the speech
  dictionary and writes the recording's summary; it uses the thinking model
  when unset.
- **Image Generation** creates task artwork and other generated images. The
  current built-in image-generation path uses a configured remote provider, so
  choose that provider and the references you send with the same care as any
  other cloud inference route.
- **Read aloud** is the cloud speech model that reads summaries and answers
  aloud; it uses the on-device voice when unset.

Under **Automated Skills** at the end of the form, switch on which skills —
transcription and image analysis — run on their own with this profile. Each
uses the model of its slot, so the switch needs that slot filled.

**Desktop Only** hides a profile on mobile platforms, which is useful when it
depends on a model reachable only from a workstation. Device pinning is for
automated synced-audio processing: pin only when the selected device advertises
the providers needed by the profile. With no pinned device, synced audio is not
automatically transcribed by that profile.

## Choose a model without memorizing IDs

Model pickers start with the provider and show only compatible saved models.
The picker in a profile slot, for example, will not offer an audio-only model
for text reasoning.

## Set a category default

A category can choose a default inference profile under **Settings →
Definitions → Categories**. An agent runs on the profile picked for it; without
one it follows its category's profile on every run, so changing the category's
profile moves its agents along. Without either, it falls back to the
**Default inference profile** at the top of AI Settings. Select the profile
whose privacy and capability mix matches the category rather than choosing
solely by speed.

## Legacy profile route

The older standalone **Inference Profiles** route remains available for
compatibility and edits the same stored profile records. It exposes internal
model IDs and provides less dependency context than AI Settings, so prefer the
current **AI Settings → Inference Profiles** page for normal maintenance.
