# Use Advanced Settings safely

Open **Settings → Advanced Settings** for power-user controls, diagnostics, and
maintenance. It lists **Config Flags**, **GitHub**, **Language**, **Logging
Domains**, **System health**, **Maintenance**, **Onboarding Metrics** and
**About Lotti**; on iOS and Android, **Health Import** appears between **System health** and
**Maintenance**. These pages either change how Lotti runs or act directly on local
data, so ordinary personalization belongs elsewhere in Settings.

Desktop keeps the settings tree beside the selected page. Mobile opens one
page at a time and provides a back button. The same controls and persisted
values are used in both layouts.

## Choose the app and Manual language

Open **Language** to set the language Lotti itself uses. The same choice decides
which published Manual the app opens. **Follow system** is the default: Lotti
uses your device language where it is supported, and English otherwise. Pick any
language listed on that page to persist a different choice — the interface
switches with it, not only the documentation link. The Manual entry at the
bottom of Settings and **Help → Manual** on macOS both follow this setting.

## Control capabilities with Config Flags

<ManualScreenshot
  caseId="advanced-settings/flags"
  alt="Lotti Config Flags page with a Search flags field and switches grouped under Preferences, starting with private entries, location recording, tooltips, and session ratings, then Advanced & experimental"
  caption="Search matches both flag names and descriptions. Each switch changes its stored runtime capability immediately."
/>

**Config Flags** is the capability switchboard. Rows are grouped into
**Preferences**, the settings you might reasonably want to change, and
**Advanced & experimental**, which is diagnostics and unfinished work.

- **Preferences:** private-entry visibility, location capture, tooltips,
  session ratings, What's New, AI response streaming, AI summary playback, and
  Matrix sync.
- **Advanced & experimental:** the experimental task chat, the companion and
  its chat (see [Talk to your companion](../getting-started/companion.mdx)),
  embeddings, syncing embeddings and vector search, the Daily OS walkthrough,
  agent fork healing, the background sync worker, logging, and resending
  failed attachments.

Notification switches live in **Settings → Notifications**. Whole app sections such as Habits, Projects, and Daily OS
are no longer here; they live in [Sections](./settings.mdx).

Use **Search flags** to narrow the list by title or description. Select a row
or its switch to change the flag. The new value is saved immediately; there
is no separate Save action.

Flags can expose experimental or diagnostic behavior. Change one deliberately,
then verify the affected workflow before changing another. The **Show private
entries?** flag controls whether sensitive content is included across lists and
selectors; it does not encrypt, export, delete, or change the privacy of an
entry.

## Choose what Lotti logs

<ManualScreenshot
  caseId="advanced-settings/logging"
  alt="Lotti Logging Domains page with the Enable Logging master switch above per-domain switches such as Sync, AI, Chat, Speech & audio, Database, and Tasks & checklists"
  caption="The master switch gates the per-domain controls. The Project Waddle fixture keeps Sync, AI, and Tasks enabled for focused diagnostics."
/>

**Logging Domains** starts with the global **Enable Logging** switch. When it
is on, enable only the domains needed for an investigation — among them
**Sync**, **AI**, **Chat**, **Speech & audio**, **Database**, **Agent
runtime**, **Tasks & checklists**, **Labels**, **Health**, **Habits**,
**Navigation**, **Notifications** and **Daily OS**. **Slow Database Queries**
writes slow database queries to their own daily `slow_queries-*.log`.

Turning off the master switch disables the domain controls. Errors are still
written to the daily `error-*.log`; these switches govern additional diagnostic
logging, not the minimum error record. Disable noisy domains after an
investigation so logs stay focused and storage use remains predictable.

## Read a system health report

**System health** turns the log files Lotti keeps on this device into a short
report you can share. Choose a time range (the last 24 hours, 7 or 14 days, or
custom days), confirm which logging domains to analyze — the switches are the
same ones as in the logging section above, so a domain that is switched on is
both logged *and* analyzed — and pick the model that writes the findings. Lotti
proposes the thinking model of your default inference profile.

Before anything is analyzed, known personal-data patterns in the log lines
are replaced with placeholders: email addresses, identifiers, access tokens,
file paths that include your user name, IP addresses and phone numbers. Error
text comes from the safe error log, which never carries the raw exception.
Free text inside a log message is not scrubbed, so the report is only as
clean as the log lines it was built from. The report
lists the three findings that most deserve attention, each with the evidence,
the likely cause and a next step, and keeps the condensed digest underneath.
**Copy report** puts the whole thing on the clipboard as Markdown, ready for a
bug report or a coding assistant. Every report is also saved beside the log files: the newest one is shown
again the next time you open the page, earlier ones are listed under
**Previous reports**, and the report on screen always says which period it
analyzed and when it was generated.
Without a model, or if the model call fails, you still get the digest.

## Connect GitHub

**GitHub** holds the read-only personal access token Lotti uses to read the
pull requests you link to tasks. **Create a token on GitHub** opens GitHub's
token form with the permissions filled in; choose your repositories, paste the
token into **Personal access token** and select **Connect**. The page then
shows which account is connected and offers **Disconnect**. The token syncs
end-to-end encrypted to your other devices and is used only for requests to
api.github.com. With it connected, the companion can also answer questions
about your pull requests. See [Connect GitHub](./github.mdx) for tracking pull
requests on tasks and what the AI does with them.

## Run maintenance actions deliberately

<ManualScreenshot
  caseId="advanced-settings/maintenance"
  alt="Lotti Maintenance page with onboarding previews, reset actions, database integrity check, database deletion, purge, full-text index, screenshot storage repair, embeddings, and the repaint rainbow overlay switch"
  caption="Maintenance combines safe previews with destructive and diagnostic actions. Read the confirmation and scope before continuing."
/>

**Maintenance** contains several different kinds of action:

- **Show onboarding welcome** and **Onboarding animation gallery** are live
  previews for development and QA.
- **Reset In-App Hints** makes one-time tips eligible to appear again.
- **Reset Gemini Setup Dialog** clears its dismissal so the provider prompt can
  be tested again.
- **Check database integrity** verifies that the database files are sound.
- **Delete Editor Database** removes editor drafts.
- **Delete Agents Database** removes the agents database and exits Lotti so the
  app can restart against a clean store.
- **Purge deleted items** permanently clears soft-deleted records through a
  dedicated confirmation flow.
- **Recreate full-text index** rebuilds local search data without recreating
  journal entries.
- **Repair screenshot storage** moves screenshots saved by older versions into
  the correct folder so AI image analysis can read them.
- **Generate Embeddings** appears when the embedding store is available and
  backfills selected categories.
- **Repaint rainbow overlay** flashes repainting regions for UI diagnostics. It
  is held in memory and returns to off after relaunch.

Preview and reset actions do not share the same risk as deletion and purge.
For destructive actions, confirm that the target is the intended local store
and let any current sync or write operation finish first.

## Inspect the onboarding funnel

<ManualScreenshot
  caseId="advanced-settings/onboarding-metrics"
  alt="Lotti Onboarding Metrics page showing install time, four active days, activation status, and content-free event counts"
  caption="The deterministic manual fixture reached its real aha across four active days after connecting a provider and recording several captures."
/>

**Onboarding Metrics** is a developer and QA surface. It derives a local funnel
from content-free events and shows:

- the first-seen timestamp in UTC;
- total active days and active days during the first seven days;
- whether the install belongs to the pre-FTUE baseline cohort;
- whether the real activation milestone was reached; and
- a count for every onboarding event.

The page records event names and low-cardinality metadata, not journal text,
task titles, transcripts, or the sardine-sensitive details of Project Waddle.

**Reset onboarding test state** clears onboarding prompt cadence and the local
funnel metrics after confirmation. It does not delete journal data, config
flags, or real Daily OS plan history. A profile that has already planned a day
therefore remains ineligible for the exact clean-profile first-plan path.

## Verify the build and local totals

<ManualScreenshot
  caseId="advanced-settings/about"
  alt="Lotti About page showing version, platform, build type, 2604 journal entries, 11 flagged entries, and task counts"
  caption="About Lotti identifies the running build and summarizes local data. The Project Waddle fixture contains 2,604 entries and 65 tasks across five states."
/>

**About Lotti** is the fastest place to verify which build is actually running.
It shows the app version and build number, platform, and build type. Include
those values in a diagnostic report so a behavior can be matched to the right
code and release.

The **Your Data** card summarizes local journal entries, flagged entries, and
task counts split into Open, In Progress, On Hold, Blocked, and Done. The
manual's established Project Waddle workspace demonstrates a non-empty account:
2,604 journal entries, 11 flagged entries, and 65 tasks rather than placeholder
zeros.

**[Customize completion celebrations](./completion-celebrations.mdx)** for the
Animations page and its live playground.
