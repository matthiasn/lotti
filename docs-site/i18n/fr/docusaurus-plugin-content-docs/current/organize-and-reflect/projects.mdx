# Mener le travail en projets

Les projets se situent entre les catégories et les tâches. Une catégorie comme **Opérations pingouins** définit un domaine de responsabilité large ; **Project Waddle** regroupe les tâches concrètes nécessaires pour préparer l’habitat orbital des manchots.

## Trouver le bon projet

La recherche parcourt les titres de projet, le texte enregistré dans les projets et les noms de catégories. Sous le champ de recherche, **Actuels** masque les projets terminés et archivés ; **Tous** les fait réapparaître. **Trier les projets** ordonne la liste par **Nécessite ton attention**, **Date cible**, **Récemment mis à jour** ou **Nom**.

Le bouton de filtre limite la liste par **Statut** ou **Catégorie**. Deux interrupteurs ajoutent d’autres critères : **Seulement les résumés obsolètes** garde les projets dont le résumé de l’agent est en retard, et **Afficher le profil d’inférence** étiquette chaque projet doté d’un agent avec le nom de son profil d’inférence. Un filtre ne prend effet que lorsque tu sélectionnes **Appliquer**.

Les projets restent regroupés par catégorie après filtrage. Cela permet de distinguer plus facilement les efforts aux noms proches et de garder chaque domaine opérationnel visible. Chaque en-tête de catégorie peut être replié, et son bouton de carte ouvre **Explorer la catégorie** — les projets de la catégorie sous forme de quartier à parcourir.

## Créer un projet

Sélectionne le bouton **+** dans Projets, puis saisis :

- un titre obligatoire ;
- une catégorie facultative ; et
- une date cible facultative.

<ManualScreenshot
  caseId="projects/create"
  alt="Formulaire Créer un projet pour Établir la réserve lunaire de sardines dans la catégorie Opérations pingouins"
  caption="Le formulaire de création s’affiche dans une feuille inférieure sur mobile et dans une boîte de dialogue centrée sur ordinateur."

Un nouveau projet commence à l’état **Ouvert**. Si sa catégorie possède un modèle d’agent de projet, Lotti provisionne aussi cet agent après l’enregistrement du projet. Le projet fonctionne normalement même sans modèle correspondant.

Choisis un titre qui décrit le résultat ou la mission durable. « Établir la réserve lunaire de sardines » est plus parlant que « Sardines ».

## Modifier les réglages d’un projet

La route des réglages de projet fournit l’éditeur de formulaire complet pour l’état, le titre, la date cible, la santé, l’affectation d’agent, les changements d’agent proposés et les tâches liées. Les actions **Annuler** et **Enregistrer** restent également ancrées en bas : les modifications de formulaire en attente sont explicites.

## Comprendre l’état d’un projet

| État | Utilise-le lorsque |
| --- | --- |
| Ouvert | Le projet existe, mais son exécution active n’a pas commencé. |
| Actif | Le travail avance actuellement et mérite de figurer dans la planification quotidienne. |
| Surveillance | Aucun travail n’est planifié, mais le résultat doit encore être observé. |
| En attente | Le travail est en pause pour une raison connue. |
| Terminé | Le résultat attendu a été atteint. |
| Archivé | Le projet est conservé pour l’historique, mais n’est plus opérationnel. |

Sélectionne la pastille d’état sur la page de détail du projet pour le modifier. Les changements d’état, de catégorie et de date cible sont enregistrés immédiatement ; cette surface de détail, axée sur la lecture, ne possède pas de bouton d’enregistrement séparé.

La carte **Résumé IA** rassemble l’évaluation et le rapport :

- **Santé du projet** résume l’évaluation de l’agent, avec son explication et son niveau de confiance lorsqu’ils sont disponibles, ainsi que le nombre de tâches bloquées ;
- le rapport fournit une synthèse actuelle, et **Lire plus** le développe jusqu’à son contenu complet ; et
- les prochaines étapes et les modifications proposées attirent l’attention sur des actions concrètes.

Dans Project Waddle, une évaluation **Sur la bonne voie** est encourageante, mais le distributeur de poissons en apesanteur bloque toujours le lancement. Lis l’explication avant de traiter cette évaluation comme un verdict.

La carte elle-même ne garde que **Détails de l'agent**, et **Mettre à jour** tant que le résumé est obsolète. La configuration du modèle, les mises à jour automatiques et la fréquence de mise à jour de l’agent se trouvent dans les détails internes de l’agent. Sans agent, la carte propose **Assigner un agent** et le détail continue d’afficher les tâches et la description du projet.

**Explorer le projet**, à côté du menu du projet, ouvre le projet sous forme de quartier à parcourir, avec un bâtiment pour chaque tâche.

## Ajouter des notes, des enregistrements et des images à un projet

Une barre en bas de la page du projet ajoute directement des éléments au projet : **Enregistrer une note vocale**, écrire une note, importer une image, ou le plus pour le menu **Ajouter** avec le reste. Sur un écran étroit, les boutons de note et d’image cèdent la place au plus. Tout ce qui est ajouté là est lié au projet, apparaît dans sa chronologie et est lu par son agent.

## Garder le travail du projet dans les tâches

<ManualScreenshot
  caseId="projects/tasks"
  alt="Panneau de tâches de Project Waddle listant l’inspection de l’habitat, le calibrage du distributeur de poissons en apesanteur et la confirmation des capsules de fret de sardines avec estimations et états"
/>

Les lignes de tâche d’un projet affichent le titre, un court résumé, l’estimation et l’état actuel de chaque tâche. Sélectionne une ligne pour ouvrir la tâche elle-même. Les détails de tâche restent la source de vérité pour les descriptions, enregistrements, listes de contrôle, images, relevés de temps et illustrations de couverture.

Affecte une tâche à un projet depuis le contrôle de projet dans l’en-tête de la tâche. Les projets sont délimités par catégorie : donne donc une catégorie à la tâche avant de choisir un projet. L’agent de la tâche peut aussi le proposer : mentionne le projet dans les notes de la tâche ou dans un enregistrement, et l’agent suggère d’y déplacer la tâche — ou, quand la catégorie n’a pas de projet de ce nom, de créer le projet avec la tâche dedans. Rien ne change avant que tu confirmes. Une tâche appartient à un seul projet au plus ; affecter un autre projet déplace le lien au lieu de le dupliquer.

## Projets, catégories et tâches

Utilise délibérément les trois niveaux :

- **Catégorie :** un domaine opérationnel durable, tel qu’Opérations pingouins.
- **Projet :** un résultat nécessitant plusieurs tâches, tel que Project Waddle.
- **Tâche :** une unité exécutable, telle que recalibrer le distributeur de poissons en apesanteur.

Évite de créer un projet pour une seule action simple. Crée-en un lorsque plusieurs tâches ont besoin d’une date cible, d’un état, d’un avancement agrégé ou d’un rapport opérationnel commun.
