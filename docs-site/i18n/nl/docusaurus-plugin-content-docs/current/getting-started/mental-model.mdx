## De bouwstenen, zonder te doen alsof ze allemaal hetzelfde zijn

| Bouwsteen | Gebruik het voor | Voorbeeld |
| --- | --- | --- |
| Categorie | Een betekenisvol levens- of werkgebied | Gezondheid, gezin, onderzoek |
| Taak | Een uitkomst die vooruitgang nodig heeft | De V1-release voorbereiden |
| Checklist | Concrete stappen binnen een taak | Releasenotities verifiëren |
| Invoer | Context of bewijs | Notitie, afbeelding, audio-opname |
| Gepland blok | Een voorgesteld slot op de dag | Releasebeoordeling, 10:00–11:00 |
| Tijdregistratie | Wat er feitelijk is gebeurd | Releasebeoordeling, 10:18–11:07 |
| Gewoonte | Een terugkerend gedrag dat je evalueert | Medicijnen innemen |
| Meetbaar | Een numerieke observatie | Hartslag in rust |
| Dashboard | Een overzicht van nuttige metingen | Trainingsoverzicht |

## Agenten zijn gasten, geen mede-eigenaren

Een agent kan de context lezen die je hem geeft, een mening vormen, een rommelige
taak samenvatten en een nuttige volgende wijziging voorstellen. Zijn verslag is een
mening met herkomst, geen nieuw feit in je geschiedenis. Voorgestelde wijzigingen aan
taak, checklist, status of datum wachten tot jij ze bevestigt of afwijst. De
uitzonderingen zijn de titel en de taal: elk wordt meteen toegepast wanneer *dat veld*
nog leeg is en de agent het voor het eerst instelt. De rest van de taak mag vol werk
zitten — een taak met een beschrijving, checklists en geregistreerde tijd, maar zonder
ingestelde taal, krijgt haar eerste taal zonder vragen toegepast. Zodra een veld een
waarde heeft, geldt dezelfde regel voor menselijke goedkeuring.

Dit is geen beleefdheid die op een prompt is vastgeschroefd. Lotti houdt het
persoonlijke logboek en het werkgeheugen van de agent gescheiden, zodat de agent je
geschiedenis niet als kladblok kan behandelen. Je kunt AI gebruiken, afstemmen of
helemaal met rust laten.

## Een praktische eerste omloop

1. Maak categorieën die je echt gebruikt om beslissingen te nemen.
2. Leg werk vast als taak en houd ondersteunend materiaal daaraan gekoppeld.
3. Gebruik Daily OS om te beslissen wat er op een bepaalde dag thuishoort.
4. Leg werkelijke tijd en observaties vast zonder ze te dwingen bij het plan te
   passen.
5. Bekijk gewoonten en dashboards op patronen in plaats van op losse perfecte
   dagen.

## Houd het eigendom duidelijk

- Een gekoppelde taak is eigenaar van haar titel en categorie.
- Een Daily OS-blok is eigenaar van zijn plaatsing en duur.
- Een tijdregistratie is eigenaar van het verslag van wat er is gebeurd.
- AI stelt voor; jij beoordeelt en beslist.

:::tip[Het punt is geen vlekkeloze tijdlijn]

Als het plan is veranderd, laat het dan veranderen. Als de dag zijwaarts ging, noteer
dan wat er wél gebeurde. Een nuttig systeem helpt je de vorm van je leven te zien;
het vraagt je niet om voor de database een productiever leven op te voeren.

:::
