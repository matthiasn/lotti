# O teu primeiro dispositivo

:::note[Pré-requisito]

Esta página exige um homeserver Matrix (Synapse) operado por você ou por alguém de sua confiança, além de acesso de administrador. Se você não tiver um, este caminho não está disponível — e nada mais no Lotti depende dele.

:::

Cada dispositivo depois do primeiro recebe o seu código de emparelhamento de
um dispositivo que já usas — esse percurso é
[Adicionar um dispositivo](./add-device.mdx). O primeiro é diferente: não há
outro dispositivo que possa gerar um código. A sincronização do Lotti é
auto-hospedada, por isso o primeiro código vem do lado do servidor — criado
por quem administra o teu homeserver Synapse.

## O que faz a ferramenta de provisionamento

O Lotti inclui uma CLI de administração, o **provisionador Matrix**, no
repositório em
[`tools/matrix_provisioner`](https://github.com/matthiasn/lotti/tree/main/tools/matrix_provisioner).
Executada por um admin do homeserver:

1. cria uma conta Matrix nova dedicada à sincronização,
2. cria a sala de sincronização cifrada, e
3. escreve num ficheiro um **bundle de provisionamento** — o texto que o
   Lotti aceita como código de emparelhamento.

O README ao lado da ferramenta documenta a configuração inicial, cada argumento e as formas seguras
de fornecer a palavra-passe de admin. Uma execução mínima é assim:

```bash
cd tools/matrix_provisioner
python provision.py \
  --homeserver https://matrix.example.com \
  --admin-user admin \
  --username lotti_sync_user42 \
  --output-file bundle.txt
```

Se não administras o teu próprio homeserver, este passo não é teu — pede o
bundle a quem opera o servidor, e trata o caminho por onde ele te chega com
o cuidado descrito abaixo.

## Usar o bundle como primeiro código de emparelhamento

No dispositivo que vai ser o teu primeiro, abre **Definições →
Configurações de sincronização → Dispositivos** e escolhe **Configurar
sincronização**. Cola o texto do bundle no campo do código — num telemóvel,
onde a câmara abre primeiro, escolhe **Colar o código em alternativa** para
lá chegar. Revê o que o código descreve e liga — para um primeiro
dispositivo, o percurso acaba aí. Não há verificação por emojis aqui: a
verificação compara dois dos teus dispositivos, e só tens um. A cerimónia
aparece pela primeira vez quando emparelhas o teu segundo dispositivo com
[Adicionar um dispositivo](./add-device.mdx).

Também vale a pena saber: consumir um bundle de provisionamento
fresco **roda a palavra-passe da conta** ao ligar. O ficheiro do bundle fica
gasto após o primeiro uso — a credencial viva passa a existir apenas nesse
dispositivo, e cada dispositivo seguinte emparelha a partir de um existente
com [Adicionar um dispositivo](./add-device.mdx). Apaga o ficheiro do bundle
assim que o primeiro dispositivo estiver ligado; uma cópia esquecida já não
consegue iniciar sessão, mas não há razão para a manter.

Até esse primeiro uso, trata o bundle como uma palavra-passe: ele inicia
sessão na conta de sincronização — mantém-no fora de conversas, capturas de
ecrã e ecrãs partilhados.

## No Linux: entrar sem bundle

O pré-requisito acima tem uma exceção. No Linux, **Configurar a
sincronização** oferece também **Em vez disso, entrar com uma conta Matrix**,
e o cartão do primeiro dispositivo na página do código de emparelhamento traz
a mesma opção. Introduz o endereço do servidor, o teu ID Matrix completo
(como `@nome:example.com`) e a palavra-passe da conta: o Lotti entra, cria
ele próprio a sala de sincronização encriptada nessa conta e chega ao mesmo
ecrã de primeiro dispositivo em que termina o caminho do bundle. Sem
administrador, sem ferramenta, sem bundle — serve qualquer conta Matrix que
controles, no teu próprio homeserver ou num público.

Duas coisas a saber. Usa uma conta reservada à sincronização, não uma com
que conversas: a sala de sincronização é apenas mais uma sala dessa conta, e
tudo o que escreves vai para lá. E aqui a palavra-passe é tua — fica no
armazenamento seguro deste dispositivo, só é enviada ao servidor que
indicares e **nunca é rodada**, ao contrário do bundle acima. Cada
dispositivo seguinte continua a emparelhar-se a partir deste com
[Adicionar um dispositivo](./add-device.mdx).
