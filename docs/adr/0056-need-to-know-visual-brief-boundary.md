# ADR 0056: The Need-to-Know Visual Brief Boundary

- Status: Proposed
- Date: 2026-08-08

## Context

Goal-agent text inference runs on the user's configured zero-retention-posture provider (today:
Melious.ai — EU jurisdiction, no-training claims; `PRIVACY.md` records that these are the
provider's claims on the provider's terms). Ad images are generated by **Nano Banana Pro**
(`models/gemini-3-pro-image-preview`, direct Gemini) — a provider for which zero data retention
**cannot** be enforced. The user's ruling (2026-08-08): we shall not share anything with the
image provider beyond the actual image request — zero background information, strict
need-to-know.

Prior art in-repo: the "Generate Cover Art (Flux)" skill already composes a compact visual scene
prompt with a no-readable-text contract (`built_in_skills.dart`); ADR 0034 established the
deterministic-validation + one-repair-call + typed-failure shape for AI output gating.

## Decision

1. **Non-ZDR providers receive a self-contained typed brief — nothing else.** The outbound image
   request is built from a `GoalNudgeBrief` value object (`sceneConcept`, `mood`, enum
   `stylePreset`, `paletteHint`, `aspectRatio`, `composition`) plus a fixed style-contract system
   message (16:9, centre-safe, **no readable text, captions, UI, logos, or watermarks**). The
   brief must be understandable by someone with zero knowledge of the user.

2. **The parameter type enforces the channel; evals police the content.** The type guarantees
   what it can: the request builder's entire input *is* the brief —
   no repository handle, no entity, no conversation context exists in its signature or call
   path. Personal data cannot be attached because no parameter can carry it. The shared image
   service (extracted from `SkillInferenceRunner.runImageGeneration`) is capability-shared with
   task cover art, but need-to-know lives at each caller: cover art legitimately builds its
   prompt from task context; the ad path structurally cannot. What the type cannot prevent is
   the model writing personal data *into* a free-text brief field — that residual channel is
   Decision 4's linting plus the leakage evals (Decision 6), never the type alone.

3. **Only leakage-checked fields leave the device.** (Revised 2026-08-08 with ADR 0055
   Decision 8.) The `headline` and optional `cta` ARE part of the outbound request — rendered as
   banner typography — because they are model-authored brief fields covered by the same
   constitution rules, handler linting and leakage evals as `sceneConcept`; by construction they
   carry no personal data ("3,200 steps to go" is exactly what the lint rejects). `caption`,
   `altText` and any goal-referencing copy remain entity-only and are never sent. The boundary
   is the *field allowlist*, not the absence of text.

4. **Defense-in-depth behind the type.** The agent authors the brief via a schema-constrained
   tool call; the goal constitution forbids names, health readings, locations, dates, or numbers
   from context in any brief field; and the tool handler lints briefs (digit+unit patterns,
   terms from the goal title, entries from the private-strings inventory) and rejects rather
   than sanitizes. The model writing personal data into a brief is the residual channel — which
   is why it is evaluated (Decision 6).

5. **Reference images are provenance-gated.** For persona/series consistency the request may
   attach prior *AI-generated* anchors only: any referenced `JournalImage` must carry non-null
   `aiAttribution`. User photographs structurally cannot enter the ad path.

6. **Verified by evaluation, continuously.** The goal-agent eval suite includes
   leakage-pressure scenarios: the wake context is deliberately stuffed with tempting private
   detail (names, health readings, appointments), and the composed brief is asserted to contain
   **zero** strings from the fixture's private inventory, plus no self-referential fragments
   ("her goal", "as discussed"). A model that leaks fails the suite regardless of how good its
   images are.

7. **Image verification is cheap and bounded.** One flash-class vision call scores
   `{matchesBrief, mismatches[]}` against the brief (the brief is already provider-safe, so the
   verifier may run anywhere); on mismatch, exactly one regeneration with the mismatches
   appended as corrections; on second failure the ad is not published — typed failure, status
   `failed`, agent observation recorded. The ADR 0034 shape, applied to pixels.

## Consequences

- Provider choice becomes a quality decision, not a privacy decision: Nano Banana Pro (reference
  images, best quality) by default; Melious `flux-2-klein-9b` as a fallback (no reference
  images) — both sit behind the same boundary.
- The boundary generalizes: any future non-ZDR capability (video, music) adopts the same rule —
  self-contained typed artifacts out, nothing else; personal text composited locally.
- Costs: the boundary adds at most one verification call and one retry per ad — cents, recorded
  per-goal via the existing consumption attribution.
- The residual risk is the model embedding personal data in `sceneConcept` despite constitution,
  lint, and evals; the lint rejects the obvious cases and the eval suite keeps the pressure
  visible per model. This residual is accepted and documented.
